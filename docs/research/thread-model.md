# 스레드 모델 판단 (P3-10, P6-07)

- 현재 모델: 블로킹 워커 풀(keep-alive.md §4.8 1단계). 코드: `core/.../server/WorkerPool.java`, `HttpServer.java`(acceptor, watchdog).
- JVM 측정(baseline.md "새 엔진"): idle-128에서 스레드 72개(워커 64 + acceptor + watchdog + 클라이언트 측), 힙 증가 약 2 MB.

## 2단계(Selector 주차) — 판단: 착수하지 않는다 (2026-10-18)

| 기준 (P3-10) | JVM 측정 | 판단 |
|---|---|---|
| 유휴 128개의 워커 스레드 메모리가 50연결 부하 증가분의 절반 초과 | 힙: idle-128 +1.96 MB, get-50 +2.11 MB(baseline.md). 스레드는 최대 `maxWorkers` 64개로 묶여 idle-100과 idle-128이 같다(72). 스택 상주 메모리는 JVM에서 측정하지 않았다 | 힙 기준으로는 미달. 스레드 수가 상한에 묶여 있어 연결 수에 따라 늘지 않는다 |
| 50탭 30초 재로딩에서 축출 초당 1회 초과 또는 p95 +200 ms | TH-03에서 축출 뒤 새 요청이 1 s 안에 응답. 50탭은 `maxWorkers`(64) 안에 들어가 축출이 일어나지 않는다 | 미달 |

- 결론: 블로킹 워커 풀(1단계)을 유지한다. 두 기준 모두 JVM에서 충족되지 않는다.
- 재검토 조건: P10-04(AND-06)에서 스레드 스택 PSS가 기준을 넘으면 이 판단을 다시 연다.

## SSE 50개 스트림 대안(P6-07) — 판단: 현재 구조 유지 (2026-10-18)

| 기준 (P6-07) | JVM 측정 | 판단 |
|---|---|---|
| 스트림 스레드 50개의 상주 메모리 > 5 MB | 스트림 하나 = 소유 스레드 1 + 출력 버퍼 8 KB + 대기열 상한 64 KB. 힙 상한 50 × 72 KB ≈ 3.6 MB. 스택 PSS는 미측정 | 힙 기준 미달 |
| 방송 지연 p95 > 100 ms | SSE-06: 느린 구독자가 있어도 300개 이벤트를 다른 두 구독자가 지연 없이 받음(대기열에 넣고 즉시 반환) | 미달 |

- 결론: 펌프 스레드 대안에 착수하지 않는다. 재검토 조건은 AND-08 측정.
