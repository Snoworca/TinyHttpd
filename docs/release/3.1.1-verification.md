# TinyHttpd 3.1.1 verification

Requirements: FR-HTTP-004 and OPS-HTTP-002. Release tag: `v3.1.1`.

## Contract

```java
import com.snoworca.tinyhttpd.RequestTargetPolicy;

// Add this to the framework-owned TinyHttpd builder before build().
builder.requestTargetPolicy(RequestTargetPolicy.RAW);
```

The default remains `STRICT`. In RAW mode `Request.getRequestURI()` and `getQueryString()` preserve the original path/query so the integrating framework owns validation and routing. `getPath()` retains strict decoding and its existing source signature. An invalid RAW path throws an unchecked `IllegalArgumentException`; if uncaught before commitment the engine sends 400, and after commitment it aborts without finishing the response framing. Static-file and decoded router consumers remain strict. WebSocket validates its decoded path before factory side effects or the irreversible 101 response. Transport syntax, Host and body framing validation remain enabled in both modes.

## TDD and independent review

2. After the core implementation, the direct WebSocket invalid-path regression failed: 101 was emitted before the decoded-path failure.
3. Moving validation before the listener factory and upgrade made all new regressions pass.
4. Two independent reviewers inspected the engine, exception mapping, static containment, decoded router, WebSocket order and all new test files. Neither found an unresolved confirmed defect or weakened regression.

## Completed validation

- Published 3.1.0 core was downloaded from Maven Central and its SHA-256 matched the original 3.1.0 release receipt. An actual Java 8 socket probe reproduced 400/handler0 for `/x/a%2Fb`, `/x/%00`, `/x/%2e`, `/x/%2e%2e`, `/x/%ZZ`, and 200/handler1 for `/x/ok`, `/x/a//b`.
- JDK 17 clean release-staging build passed: 400 tests, zero failures/errors, 12 pre-existing known-defect skips. Android API21 signature checks and no-external-runtime-dependency checks passed.
- All five modules staged successfully: 15 binary/source/Javadoc JARs and five POMs, including project and original NanoHttpd notices. Six publication validation tests passed; private test resources are excluded.
- A separate Java 8 consumer compiled against the staged 3.1.1 core JAR and passed the exact seven-path matrix in both policies, checking raw query and path preservation. The classpath contained the release JAR, not TinyHttpd source output directories.
- Java 8 full validation initially exposed the pre-existing JDK17-specific `SocketIoSpikeTest#channelSocketIsFullDuplex` assumption. A separate reviewer reproduced it with pure JDK sockets. The installed Java 8 source confirms adaptor read/write share `blockingLock`; production TinyHttpd uses `ServerSocket` instead.
- The corrected research spike positively observes Java 8's writer waiting on the reader's monitor, releases it through a peer byte and verifies both byte streams. JDK 17 retains its full-duplex assertion. Both targeted runtime runs passed; independent review confirmed no test weakening or production exclusions. See [socket research](../research/socket-io.md).

Final actual Java 8 full build passed: 400 tests, zero failures/errors, the same 12 pre-existing skips; no tests were excluded to obtain this result. All 19 new policy regressions passed. All staged source JAR entries match the final production source files. Public publication verification will be recorded after the upload completes. No NaruServe files were modified by this work; no dependencies were added. Physical Android device verification remains outside these API21 signature checks.
